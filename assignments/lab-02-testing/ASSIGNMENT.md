# ЛР2. Тестування, діагностика та доопрацювання клієнтської частини застосунку

**Матеріали для підготовки:** [методичні вказівки](METHODICAL_GUIDE.md), [навчальний приклад](example/README.md). Чинні вимоги до роботи й оцінювання визначає завдання в Moodle.

**Тема:** тестування, діагностика та доопрацювання клієнтської частини застосунку.

**Обсяг:** 8 аудиторних годин. **Форма виконання:** індивідуально.

## Мета роботи

Набути практичних навичок автоматизованого тестування компонентів і користувацьких сценаріїв вебзастосунку, діагностики помилок у роботі інтерфейсу та перевірки їх виправлення.

## Інструменти розробки

React, Vitest, React Testing Library, Playwright, Browser DevTools, Git. Інші засоби компонентного та наскрізного тестування, передбачені силабусом, можна використовувати після погодження з викладачем.

## Загальне завдання

На основі вебзастосунку, розробленого в лабораторній роботі №1, створіть комплекс автоматизованих тестів. Перевірте функціональність і одну з властивостей якості інтерфейсу. За результатами тестування діагностуйте та виправте виявлені помилки.

Результатом роботи має бути працездатний застосунок із набором компонентних і наскрізних тестів, які можна запустити за інструкцією в README.

## Обов'язкові вимоги

### 1. Компонентне тестування

Розробіть тести для компонентів інтерфейсу. Перевірте початковий стан форми, введення коректних та некоректних даних, поведінку під час асинхронної операції та в разі помилки.

Тести мають перевіряти спостережувану поведінку: значення полів, повідомлення, доступність засобів керування та передавання даних зовнішній операції. Для контролю результатів асинхронних операцій можна використовувати тестові двійники.

### 2. Наскрізне тестування

Розробіть браузерні тести для основних сценаріїв застосунку з ЛР1:

- завантаження списку та коректне відображення отриманих даних;
- перехід від списку до сторінки окремого об'єкта;
- створення запису через форму, надсилання даних до HTTP API та відображення створеного запису;
- обробка порожнього списку, помилки завантаження та відсутнього запису;
- реакція форми на некоректне введення.

Успішний сценарій створення запису має виконуватися з робочим тестовим HTTP API. Для перевірки виняткових станів можна використовувати керовані відповіді сервера. Забезпечте відтворювані початкові дані.

Кількість тестів визначається наведеними сценаріями та функціональністю власного застосунку.

### 3. Діагностика та виправлення помилок

Виконайте всі тести. Для аналізу їх результатів використовуйте повідомлення про невдалі перевірки, Browser DevTools (Network, Console) і діагностичні засоби Playwright. Виправте виявлені помилки та повторіть відповідні й попередні тести.

Якщо тести проходять, покажіть, як за даними браузера та звітом тестування можна підтвердити коректність одного з користувацьких сценаріїв. Штучно вносити дефект у власний застосунок не потрібно.

### 4. Якість інтерфейсу

Перевірте одну з властивостей інтерфейсу: доступність засобів керування з клавіатури або адаптивність компонування. Визначте очікувану поведінку та реалізуйте відповідний браузерний тест. За потреби доопрацюйте інтерфейс.

### 5. Організація тестів

Компонентні та наскрізні тести повинні запускатися окремими командами. Тестові дані, конфігурацію та залежності необхідно організувати так, щоб повторне виконання тестів не залежало від результатів попереднього запуску.

## Git-репозиторій і README

Продовжуйте роботу в репозиторії застосунку ЛР1. Додайте вихідний код тестів, конфігураційні файли, необхідні тестові дані й файл фіксації залежностей. Зміни зберігайте змістовними комітами.

README.md має містити опис застосунку, вимоги до середовища, інструкції запуску застосунку й API та команди виконання обох наборів тестів.

## Що потрібно здати

Подайте URL Git-репозиторію. У ньому повинні бути вихідний код застосунку, тести, README та всі файли, необхідні для відтворення результату.

Короткий звіт про виконання ЛР2 оформіть у README.md або окремому REPORT.md: зазначте перевірені сценарії, результати тестування, виявлені помилки й виправлення (за наявності), результат перевірки якості. Додайте матеріали діагностики, необхідні для пояснення результату. Окремий звіт у Word або PDF не є обов'язковим.

## Захист роботи

Студент демонструє застосунок, запускає компонентні та наскрізні тести, пояснює їх призначення, очікувані результати та вибрані засоби діагностики. Викладач може запропонувати змінити або доповнити тест, знайти причину невдалої перевірки чи виправити помилку в межах власного застосунку.
