# Навчальний приклад ЛР2. Тестування планувальника завдань

Планувальник дозволяє переглядати список, відкривати деталі, створювати завдання (назва й ознака виконання) та відбирати їх за станом. Сервер Express надає HTTP API; дані зберігаються у пам'яті.

## Запуск

З цього каталогу (перевірено з Node.js 26.13.1):

    npm ci
    npx playwright install chromium
    npm run dev

Відкрийте http://127.0.0.1:4182/tasks. Перед запуском тестів зупиніть сервер:

    npm run build
    npm run test:component
    npm run test:e2e

Vitest виконує тільки тести в tests/component; Playwright – у tests/e2e. Тестовий сервер запускається з параметром --test і скидає дані перед кожним сценарієм. Через спільний серверний масив браузерні тести виконуються одним робочим процесом. Порт 4182 має бути вільним; у Linux/macOS можна вказати інший порт, наприклад PORT=4183 npm run test:e2e.

## Склад перевірок

- TaskForm.test.jsx – початковий стан, валідація, очікування операції, помилка.
- list.spec.js – список і деталі, завантаження та порожній результат, помилка API, відсутній запис.
- planner.spec.js – створення запису з реальним HTTP API, некоректне введення.
- filter.spec.js – відбір за станом і клавіатурне керування на вузькому екрані. Відбір є додатковою наявною функцією прикладу, а не вимогою розширювати застосунок ЛР1.

## Діагностика

Для аналізу невдалого тесту використовуйте повідомлення Playwright, знімок і трасу. У каталозі stages збережено матеріали попереднього демонстраційного сценарію: виправлення звернення до неправильного поля HTTP-відповіді та додавання відбору. Ці файли не потрібні для виконання ЛР2; не застосовуйте їх до власного проєкту. У разі використання старого демонстраційного сценарію додаткові перевірки list.spec.js залишаються в наборі.

Навчальний приклад демонструє методику тестування. Власний набір тестів необхідно розробити для функціональності свого застосунку.
