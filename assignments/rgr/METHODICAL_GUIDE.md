# Методичні вказівки до виконання розрахунково-графічної роботи

**Тема:** розроблення індивідуального мобільного, кросплатформеного або настільного застосунку з реальним використанням можливостей обраної платформи.

**Мета:** навчитися спроєктувати та реалізувати завершений інтерфейс, керувати станом, навігацією й даними, організувати платформну інтеграцію та підготувати результати до відтворюваного запуску, перевірки й захисту.

**Можливі технології:** React Native, Flutter, Kotlin/Jetpack Compose, Electron. Інший стек дозволяється після погодження. Для перевірки потрібне відповідне середовище: Android Studio/емулятор, фізичний пристрій, Flutter SDK або настільна ОС.

**Джерело вимог:** активність **«РГР. Мобільний застосунок за індивідуальним варіантом»** у Moodle. Вона визначає варіанти, мінімальну функціональність, необхідність PDF-звіту та **16-бальну** шкалу оцінювання. Для виконання умови допуску до іспиту за РГР потрібно отримати щонайменше **10 балів**.

**Навчальні приклади:** [React Native (Л7)](https://github.com/Aroxed/ui-programming-course/tree/main/examples/lecture-07-react-native-basics), [навігація та дані (Л8)](https://github.com/Aroxed/ui-programming-course/tree/main/examples/lecture-08-navigation-state-data), [платформні можливості (Л9)](https://github.com/Aroxed/ui-programming-course/tree/main/examples/lecture-09-platform-features), [порівняння трьох стеків (Л10)](https://github.com/Aroxed/ui-programming-course/tree/main/examples/lecture-10-comparison), [Electron (Л11)](https://github.com/Aroxed/ui-programming-course/tree/main/examples/lecture-11-electron).

## Крок 6. Відокремте стан інтерфейсу від постійних даних

Розподіліть дані за їхнім життєвим циклом:

| Приклад | Призначення | Джерело |
|---|---|---|
| Поточне значення поля | Тимчасовий стан форми | Компонент або екран |
| Вибраний запис | Навігаційний або спільний стан | Навігація чи шар стану |
| Збережені записи | Постійні дані | Файл, SQLite, сховище, HTTP API |
| Координати | Результат системної операції | Платформний сервіс |
| Помилка дозволу | Стан виконання операції | Модель стану інтерфейсу |

Для React Native зміна простого статусу:

```jsx
import { useState } from 'react';
import { Pressable, Text, View } from 'react-native';

export default function StatusExample() {
  const [completed, setCompleted] = useState(false);

  return (
    <View>
      <Text>{completed ? 'Виконано' : 'Активне'}</Text>
      <Pressable
        accessibilityRole="button"
        onPress={() => setCompleted(value => !value)}
      >
        <Text>Змінити статус</Text>
      </Pressable>
    </View>
  );
}
```

Такий стан зникає після перезапуску застосунку. Дані, які мають зберігатися, потребують окремого механізму постійного зберігання.

## Крок 8. Реалізуйте одну платформну можливість

Візьмемо геолокацію у React Native з Expo. У репозиторії Л9 є готовий модуль [`platform/location.js`](https://github.com/Aroxed/ui-programming-course/blob/main/examples/lecture-09-platform-features/platform/location.js), що опрацьовує дозвіл та повертає результат.

Використання в компоненті:

```jsx
const [location, setLocation] = useState({ status: 'idle' });

async function handleLocation() {
  setLocation({ status: 'loading' });
  const result = await readCurrentLocation();
  setLocation(result);
}
```

Перед цим імпортуйте `useState` і `readCurrentLocation` з власного сервісного модуля, як зроблено у Л9. Інтерфейс має розрізняти щонайменше `loading`, `denied`, `error` і `ready`.

Для Electron основний процес виконує системні операції через IPC. У Л11 [`preload.js`](https://github.com/Aroxed/ui-programming-course/blob/main/examples/lecture-11-electron/app/preload.js) відкриває renderer-процесу обмежені операції:

```javascript
const { contextBridge, ipcRenderer } = require('electron');

contextBridge.exposeInMainWorld('desktopAPI', {
  saveTask: task => ipcRenderer.invoke('task:save', task),
  openTask: () => ipcRenderer.invoke('task:open')
});
```

В основному процесі реєструються відповідні `ipcMain.handle`. Саме там можна виконувати системний файловий діалог, перевіряти дані та записувати їх у файл. Властивості `contextIsolation: true`, `nodeIntegration: false` і `sandbox: true` залишаються частиною безпечної конфігурації прикладу.

Для Flutter або Compose оберіть платформний API, що відповідає вашій темі, і перевірте його на цільовому пристрої. Імітація результату без фактичного доступу до можливості пристрою не підтверджує виконання цієї вимоги.

**Контрольна точка:** результат отримано від реального пристрою чи ОС; відмову в доступі або скасування операції опрацьовано.

## Крок 9. Додайте постійне зберігання даних

Для React Native розгляньте AsyncStorage – приклад використання наведено в [модулі зберігання Л9](https://github.com/Aroxed/ui-programming-course/blob/main/examples/lecture-09-platform-features/platform/storage.js). Дані зберігають у форматі JSON:

```javascript
const STORAGE_KEY = 'student-parking-records';

export async function saveRecords(storage, records) {
  await storage.setItem(STORAGE_KEY, JSON.stringify(records));
}

export async function loadRecords(storage) {
  const raw = await storage.getItem(STORAGE_KEY);
  return raw ? JSON.parse(raw) : [];
}
```

`storage` у цих функціях – переданий адаптер з методами `getItem` і `setItem` (наприклад, AsyncStorage). Під час інтеграції передбачте обробку пошкоджених JSON-даних, помилок доступу та повторного запуску застосунку.

Для Electron приклад Л11 використовує `fs.writeFile` і `fs.readFile` після вибору користувачем шляху в системному діалозі. Для Flutter та Compose можна використати відповідні рішення локального сховища або SQLite.

**Контрольна точка:** після перезапуску застосунку збережений запис відновлюється; у випадку відсутніх чи некоректних даних показано зрозумілий стан.

| Дозвіл не запитується | Неправильний виклик API або конфігурація | Порядок запиту, налаштування застосунку |
| Функція працює в емуляторі, але не на пристрої | Різні можливості середовища | Модель пристрою, версія ОС, дозволи |
| Записи зникають після перезапуску | Дані зберігаються лише в стані UI | Постійне сховище |
| Результат системного діалогу не обробляється | Відсутній сценарій canceled | Перевірка результату операції |
| Electron renderer має прямий доступ до Node.js | Порушена межа привілеїв | Preload, IPC, context isolation |
| UI не показує повідомлення після помилки | Немає моделі станів виконання | Error/denied/unavailable у UI |
| Застосунок складно зібрати на іншому ПК | Неповні інструкції | Версії SDK, залежності, README |
| Статичні екрани без дій | Відсутній завершений сценарій | Події, зміна стану та збереження |

- [ ] Є перевірка введення та релевантні виняткові стани.
- [ ] Платформна можливість використовує реальний API й перевірена у відповідному середовищі.
- [ ] Підготовлено README з точними командами та Git-репозиторій.
- [ ] Підготовлено PDF-звіт і результати перевірки сценаріїв.
