# Розрахунково-графічна робота

**16 балів**

## Тема

Розроблення індивідуального мобільного, кросплатформеного або desktop UI-застосунку.

## Мета

Поглибити практичні навички проєктування і реалізації завершеного інтерфейсу користувача з використанням компонентного підходу, стану, подій, навігації, даних і можливостей обраної платформи. Результатом має бути працездатний застосунок, який студент може запустити, продемонструвати, пояснити та змінити під час захисту.

## Допустимі технології

- React Native;
- Flutter;
- Electron;
- нативний Android (Kotlin / Jetpack Compose);
- інша технологія — після погодження з викладачем.

Технологія має відповідати задачі. Сам факт використання певного framework не є перевагою під час оцінювання.

## Загальне завдання

За своїм варіантом розробіть невеликий, але завершений UI-застосунок. Він повинен підтримувати щонайменше **три завершені сценарії користувача**.

Приклади сценаріїв:

- список → деталі → зміна статусу;
- створити → перевірити введення → зберегти;
- викликати platform feature → отримати результат → відобразити його;
- відкрити локальний файл → змінити дані → експортувати результат.

## Обов'язкові вимоги

1. **Компонентна структура.** UI розділено на логічні компоненти, віджети або Composable-функції.
2. **Стан і події.** Стан реально змінюється внаслідок дій користувача і впливає на UI.
3. **Навігація.** Є щонайменше два змістовні екрани/представлення або інша явна navigation structure.
4. **Дані.** Використовується local storage, файлова система, SQLite/інша локальна БД, HTTP API або інше погоджене джерело.
5. **Зміна даних.** Користувач може створити, змінити, видалити або інакше змістовно модифікувати дані.
6. **Валідація.** Некоректне введення не приводить до виконання операції без пояснення користувачу.
7. **Платформна можливість.** Реалізовано щонайменше одну реальну інтеграцію: camera/image picker, geolocation, notifications, native sharing, permissions, local file dialogs, application menu, clipboard, системне сховище або іншу погоджену можливість.
8. **Стани виконання.** Оброблено релевантні empty/loading/error/canceled/permission denied/unavailable states.
9. **Перевірка.** Перед захистом перевірено не менше трьох основних user flows.

РГР не вважається завершеною, якщо це набір статичних екранів без стану і даних, копія навчального прикладу лише зі зміненими текстами/кольорами, або якщо заявлена platform feature імітується замість роботи з реальним API чи можливістю середовища.

## Що потрібно здати

- посилання на GitHub-репозиторій;
- `README.md` з точною інструкцією запуску;
- звіт у PDF;
- готовий до демонстрації застосунок або reproducible development run;
- за потреби тестові дані, `.env.example` та інші файли, потрібні для відтворення запуску.

## Вимоги до репозиторію

- власні source-файли, конфігурація та lock-файл;
- без `node_modules`, build/dist, emulator images, secrets і API keys;
- осмислені проміжні commits;
- README з prerequisites, installation і точними run commands.
