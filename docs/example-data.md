# Узгоджені демонстраційні дані TaskApp

Приклади Л1–Л13 використовують зрозумілий студенту перелік завдань.
Однакові назви й початкові стани дають змогу порівнювати реалізації незалежно
від бібліотеки чи мови програмування.

| Позиція | Назва | Стан |
| --- | --- | --- |
| 1 | Підготуватися до семінару | Активне |
| 2 | Виконати лабораторну роботу | Виконано |
| 3 | Завантажити звіт у Moodle | Активне |

Файл [example-data.json](example-data.json) зберігає еталонні назви та стани.
Окремі проєкти самодостатні й використовують такі ID: Л1–Л2 – 41–43,
React і навчальний HTTP API – 1–3. Ідентифікатори потрібні для демонстрації
роботи з даними; збігатися мають **предметний зміст, порядок і стан**.

У Л3–Л4 до завдань додаються пріоритети, у Л6 – вибір, у Л8 – маршрутизація
і завантаження через API. Л9 присвячена платформним функціям та локальній
чернетці, тому початкового списку немає. У Л10 перше завдання показано
в трьох технологіях з однаковим початковим станом. У Л11 редагується третє
завдання, а Л12–Л13 використовують спільні назви в тестових сценаріях.

Л14 використовує **120 штучно створених записів** для перевірки продуктивності;
Л15 розглядає супровід програмного проєкту студента. Ці два набори
обґрунтовано відрізняються предметною метою.

Назви нових завдань, які студент вводить під час тестів, можуть відрізнятися,
зокрема «Купити продукти на вихідні», «Прочитати нову книжку»
або «Запланувати зустріч з одногрупниками». Це перевіряє роботу форми,
а не змінює еталонний початковий список.

Після оновлення текстів необхідно синхронізувати вихідні файли, API,
автоматичні тести, скриншоти та приклади у Moodle. Сценарії,
ідентифікатори й технічні контракти змінюються лише за потреби.

Для перевірки узгодженості запустіть:

```bash
python3 scripts/verify-example-data.py
```
